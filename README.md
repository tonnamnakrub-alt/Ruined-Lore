# SIDELINE

เปิดไฟล์ `sideline.html` ในเบราว์เซอร์ได้เลย ไม่ต้องลงอะไร ไม่ต้องต่อเน็ต เล่นในมือถือก็ได้

ตัวเกมเป็น **ภาษาอังกฤษ** เป็นค่าเริ่มต้น สลับเป็นไทยได้ที่ปุ่ม EN/TH มุมบนของเมนูหลัก หรือในหน้า SETTING
(ภาษาที่เลือกถูกจำไว้ในเครื่อง เปิดใหม่ก็ยังเป็นภาษาเดิม)

---

## ระบบเงิน

เงินและ XP คิดยังไง — นิสัยเลนเจอกัน ป่า ศพ พาสซีฟเลน และจุดที่ใช้ปรับบาลานซ์ อยู่ใน **[ECONOMY.md](ECONOMY.md)**

---

## มันคือเกมอะไร

สั้นๆ คือคุณเป็นโค้ชทีมอีสปอร์ต ไม่ใช่คนเล่น

คุณมีนักแข่ง 5 คน แต่ละคนไปคุมตัวละครในเกม MOBA อีกทีนึง พอไฟต์เริ่มปุ๊บคุณสั่งอะไรไม่ได้แล้ว ได้แต่นั่งดูเหมือนนั่งดูทีมตัวเองแข่งจริงๆ ทุกอย่างที่จะตัดสินว่าแพ้หรือชนะ คุณตัดสินใจไปหมดแล้วตั้งแต่ก่อนเริ่ม

แล้วนักแข่งก็ไม่ได้เก่งขึ้นระหว่างทัวร์ด้วย เหมือนคนจริงๆ ที่ฝีมือเท่าไหนก็เท่านั้นทั้งทัวร์ ที่โตได้มีแค่ของกับเลเวลของตัวละคร

---

## นักแข่งมี 5 ค่า แจกคนละ 30 แต้ม

แจกแล้วแจกเลย ซื้อเพิ่มไม่ได้ทั้งเกม

- **Precision** — ยิงสกิลแม่นไหม ต่ำๆ นี่คือยิงเฉียงไปข้างๆ เลย
- **Reaction** — หลบทันไหม เห็นวงระเบิดลงพื้นแล้วเดินออกทันหรือยืนกินเต็มๆ
- **Discipline** — ไล่ตามจนหลุดทีมหรือเปล่า ทิ้งอัลติมั่วไหม
- **Positioning** — ยืนถูกที่ไหม หรือเดินเข้าไปกลางวงศัตรูเอง
- **Awareness** — เลือกเป้าเป็นไหม เก็บแครี่หรือไปตีแทงค์

ลองเทสแล้วทีมฝีมือเทพชนะทีมฝีมือห่วยราว 70% จาก 300 ไฟต์

## เรื่องภาษา

ข้อความในซอร์สยังเป็นภาษาไทย แล้วห่อด้วย `tr("...")` — ตอนแสดงผล `tr` จะไปเปิดพจนานุกรม `i18n-en.js`
ถ้าหาไม่เจอจะคืนข้อความไทยเดิม (หน้าจอไม่พัง แค่โผล่ไทยมาคำเดียว)

เพิ่มข้อความใหม่: เขียนไทยแล้วห่อ `tr("...")` จากนั้นเติมคู่คำแปลใน `i18n-en.js`
ชื่อไอเทมไม่ต้องแปล เพราะเก็บเป็น `"English — ไทย"` อยู่แล้ว ใช้ `itemName(it)` มันเลือกข้างให้ตามภาษา

## โครงเมนู

```
MAIN MENU ─ PLAY ─ CLASSIC ─ เลือกยาว/Rush ─ สร้างทีม ─ PICK ─ จัดตำแหน่ง ─ วางแผน ─ ร้านค้า ─ ไฟต์
          │      ├ RANK (เร็วๆ นี้)
          │      ├ TOURNAMENT (เร็วๆ นี้)
          │      └ ห้องซ้อม
          ├ CHARACTER STORE (แท็บตามเลน + ราคา — ทุกตัวเล่นได้ฟรีอยู่แล้ว)
          ├ ITEM (คลังไอเทม 130 ชิ้น + สูตรคราฟต์)
          └ SETTING
```

หน้าที่เป็น "ตาราง + รายละเอียด" (PICK / STORE / ITEM) จอกว้างแสดงสองฝั่ง จอมือถือสลับเป็นตารางบน-รายละเอียดล่าง

---

## เล่นยังไง

แจกแต้มนักแข่ง (ขี้เกียจก็กด "สุ่ม + เริ่มเลย") → ดราฟต์ว่าใครคุมตัวไหน → ซื้อของกับอัพสกิล → เลือกว่ายกนี้ยาวกี่วิ → สั่งสไตล์บุก/คุมระยะ/ตั้งรับ → กดดู

เลือกโหมดได้ตอนสร้างทีม

- **ยาว — 50 ยก** ถึง 26 ก่อนชนะ (เสมอ 25-25 มียกตัดสิน) เงินกับ XP ได้ครึ่งเดียว สะสมของช้า ยกเดียวไม่พลิกทั้งแมตช์
- **Rush — 20 ยก** ถึง 11 ก่อนชนะ เงินกับ XP คูณ 2 เท่าโหมดยาว ของขึ้นไว จบไว

จบโหมดยาวจะอยู่ราว Lv16 มีของสำเร็จรูป ~4 ชิ้น / Rush ราว Lv12 กับ ~3.7 ชิ้น — พลังปลายเกมใกล้กัน แต่โหมดยาวใช้เวลามากกว่า 2.5 เท่า

ตอนดูไฟต์ **ลองแตะชื่อตัวละครข้างสนามดู** มันจะโชว์สกิล คูลดาวน์ แล้วลากเส้นบอกว่ากำลังเล็งใครอยู่ อันนี้ช่วยเยอะเวลาอยากรู้ว่าบอทมันคิดอะไรอยู่

---

## ส่องทีมคู่แข่ง

ปุ่ม **"ส่องทีมคู่แข่ง"** มีสองที่ — หน้าเตรียมยก (ก่อนกดเริ่มไฟต์) กับระหว่างไฟต์
เห็นตัวละคร ไอเทม เลเวล และสกิลที่อัพไปแล้วของทั้ง 5 เลน พร้อมสรุปมูลค่าของรวมเทียบกับทีมเรา
ระหว่างไฟต์จะเห็นเลือดสดๆ กับดาเมจสะสมของแต่ละตัวด้วย

สิ่งที่ **ไม่** โชว์คือสไตล์ที่คู่แข่งสั่ง (บุก/คุมระยะ/ตั้งรับ) — ตรงนั้นยังต้องเดาเอง

หมายเหตุ: เดิมบอทซื้อของตอนกดเริ่มไฟต์ ตอนนี้ย้ายมาซื้อตั้งแต่ต้นยกแล้ว
ของที่ส่องเห็นก่อนไฟต์เลยเป็นของจริงที่จะเจอ ไม่ใช่ของยกที่แล้ว

---

## ข้อมูลสกิล

กดที่สกิลตัวไหนก็ได้ เปิดหน้าข้อมูลขึ้นมา สลับ Q/W/E/R ในหน้านั้นได้เลย กดได้จาก

- **Character Info** ในหน้า PICK และ CHARACTER STORE
- **หน้าเตรียมยก** — กดสกิลแล้วจะเห็นว่า "อัพเป็นแรงก์หน้าได้อะไรเพิ่ม" พร้อมปุ่ม UPGRADE ในหน้านั้น
- **ระหว่างไฟต์** — แตะชื่อตัวละครให้โฟกัสก่อน แล้วกดแถวสกิล
- **หน้าส่องทีมคู่แข่ง** และ **ห้องซ้อม**

ในหน้านั้นบอก: รูปแบบสกิล (กรวย/พุ่ง/ลงพื้นเป็นวง…), ค่าทุกแรงก์เรียงให้เห็นหมด (แรงก์ที่มีอยู่ไฮไลต์ทอง
แรงก์ถัดไปขอบทอง), ค่าที่สเกลตาม AD/AP/Bonus HP, ค่าคงที่ (ระยะ รัศมี เวลาร่าย คูลดาวน์ ฯลฯ), พาสซีฟตัวละคร

ตัวเลขทั้งหมดอ่านจาก `data/champions.js` ตรงๆ ไม่ได้พิมพ์ซ้ำ — จูนบาลานซ์แล้วหน้านี้เปลี่ยนตามเอง
ถ้าเพิ่มฟิลด์ใหม่ให้สกิล แล้วอยากให้โผล่ในหน้านี้ ใส่ป้ายชื่อในตาราง `RANKED`/`FLAT`/`RATIOS` ใน `game/skill-desc.js`

## กราฟสรุปไฟต์

ปุ่ม **"กราฟ"** อยู่ในหน้าไฟต์ (ดูสดระหว่างสู้ได้เลย) และหน้าสรุปหลังจบยก
ในแมตช์เดียวกันย้อนดูยกเก่าได้ทุกยก — แถบชิปด้านบนเป็นรายการยก กด "ยกนี้ (สด)" คือยกที่กำลังสู้อยู่

- **เส้นเวลา** สลับดูได้ระหว่าง *ดาเมจสะสม* กับ *เลือดรวมที่เหลือ* ของสองทีม แตะ/ลากบนกราฟเพื่ออ่านค่าทีละจังหวะ
- **แท่งเทียบรายคน** 10 ตัวเรียงจากมากไปน้อย สลับได้ 4 มุม: ดาเมจที่ทำ / ดาเมจที่รับ / ฮีล / โล่
- **แตะชื่อ** จะกางรายละเอียดของคนนั้น: K/A เลือดที่เหลือ ออโต้เข้าเป้ากี่นัด หลบได้กี่ครั้ง
  ฮีลจ่ายออก/รับเข้า โล่ที่กางกับโล่ที่กันได้จริง ไอเทมที่ถืออยู่
  และ **ที่มาของดาเมจแยกเป็นรายการ** — สกิลไหนกี่ %, ออโต้กี่ %, ไอเทมตัวไหนทำเท่าไร
  ถ้าดูช่อง "ดาเมจที่รับ" จะบอกด้วยว่ารับมาจากตัวไหน ด้วยสกิลอะไร

ดาเมจถูกติดป้ายที่มาตั้งแต่ในเอนจิน (ดู `state.dmgSrc` ใน `engine/`) เทสแล้วดาเมจ 100% มีที่มาระบุได้
ถ้าเพิ่มสกิล/ไอเทมใหม่ที่ทำดาเมจแบบหน่วงเวลา อย่าลืมใส่ `src` ให้ออบเจกต์ที่ปล่อยออกไป ไม่งั้นจะไปกองอยู่ช่อง "อื่นๆ"

## ไอเทมสายเวท

เพิ่มชิ้นส่วน Tier 2 สายเวท 4 ชิ้น (cyw/orl/cbl/pwa) และไอเทมเวท Tier 3 อีก 15 ชิ้น รวมของทั้งเกมเป็น 92 ชิ้น
ทั้งหมดอยู่หมวด HASTE (เร่งจังหวะ) ตามที่ออกแบบไว้ — ถ้าอยากแยกเป็นหมวด MAGE ของตัวเอง เพิ่มใน `CATEGORIES` ได้

ค่าสถานะที่เพิ่มเข้าเอนจินรอบนี้ (เดิมไม่รองรับ ใส่ในไอเทมแล้วจะไม่มีผล)

| ฟิลด์ | ผล | อยู่ที่ |
|---|---|---|
| `apPct` | คูณ AP ทั้งก้อน | รองรับอยู่แล้ว |
| `msPct` | คูณความเร็วเดิน | `engine/stats.js` |
| `mrPenPct` | เจาะต้านเวทเป็น % (คิดก่อน pen แบบ flat, เพดาน 80%) | `engine/damage.js` |
| `ultCdr` | ลดคูลดาวน์เฉพาะท่าไม้ตาย | `engine/stats.js` (fullCd) |

บอทฝ่ายตรงข้ามจะไม่ซื้อของสาย AP ให้ตัวที่สเกล AD (ดูผลรวม apRatio เทียบ adRatio ของสกิลทั้งหมด) —
ไม่งั้นมาร์คแมนจะไปถือไม้เท้า

## ไอเทมสายมาร์คแมน

เพิ่มชิ้นส่วน Tier 2 อีก 4 ชิ้น (hys/asf/lbn/wtb) และไอเทมมาร์คแมน Tier 3 อีก 10 ชิ้น
รวมของทั้งเกมเป็น **106 ชิ้น** ทั้งหมดอยู่ในหมวดใหม่ `MARKSMAN` (มาร์คแมน) ใน `CATEGORIES`
และบอทเลน ADC จะไล่ซื้อหมวดนี้ก่อนเป็นอันดับแรก (`LANE_TASTE.ADC`)

ค่าสถานะที่เพิ่มเข้าเอนจินรอบนี้

| ฟิลด์ | ผล | อยู่ที่ |
|---|---|---|
| `critDmg` | ดาเมจคริแรงขึ้น (ฐาน 175% + ค่านี้) | `engine/stats.js` + `engine/step.js` |
| `armorPenPct` | เจาะเกราะเป็น % (คิดก่อน pen แบบ flat, เพดาน 80%) | `engine/damage.js` |
| `dmgAmpHighHp` | เลือด 80% ขึ้นไป ตีแรงขึ้นทุกชนิด | `engine/damage.js` |

พาสซีฟที่ไม่ใช่ค่าสถานะอยู่ใน `engine/on-hit.js` ฟังก์ชัน `marksmanOnHit()` —
นับฮิตด้วย `u.mmHits` แล้วแยกเป็นผลทุกฮิต (slh/ulf/boe) กับผลฮิตที่ 3 (ivd/sst/hth)
ตัว `hth` เรียก `marksmanOnHit()` ซ้ำด้วยแฟล็ก `echo` เพื่อไม่ให้นับฮิตซ้ำและไม่วนไม่รู้จบ
ส่วนโล่เส้นตายของ `swf` อยู่ใน `engine/damage.js` (ตอนเลือดตก) กับ `engine/step.js` (ตอนโล่หมดอายุ)

## ไอเทมสายซัพพอร์ต

เพิ่มชิ้นส่วนอีก 4 ชิ้น (pcp/isw/ccr/ngv) และ Tier 3 อีก 10 ชิ้น — สาย Enchanter 7 ชิ้น สาย Support Tank 3 ชิ้น
รวมของทั้งเกมเป็น **120 ชิ้น** อยู่ในหมวดใหม่ `SUPPORT` (ซัพพอร์ต) และบอทเลน SUPPORT ซื้อหมวดนี้ก่อนเป็นอันดับแรก

### ค่าสถานะใหม่ `hors` — Heal & Shield Power

**`hors` คนละตัวกับ `healAmp` ที่มีอยู่เดิม อย่าสลับกัน**

| ฟิลด์ | ความหมาย | คูณตอนไหน |
|---|---|---|
| `hors` | พลังฮีล/โล่ที่ยูนิตนี้ **จ่ายออก** ให้คนอื่น | คูณก่อน ตอนคำนวณจากฝั่งคนจ่าย |
| `healAmp` | ฮีล/โล่/ดูดเลือดที่ยูนิตนี้ **รับเข้า** | คูณทีหลัง ตอนเข้าตัวคนรับ |

ทั้งคู่ทำงานทั้งกับฮีล (`healUnit`) และโล่ (`grantShield`)
`tier3ScalingHors` ของ Yggdrasil นับจากไอเทมที่ไม่ใช่ START/PART/BOOTS รวมตัวมันเองด้วย (`engine/stats.js`)

**ข้อสังเกต: ตอนนี้ `hors` ไม่คูณฮีลที่ร่ายใส่ตัวเอง** (เงื่อนไข `giver !== u`)
ถ้าอยากให้คูณเหมือน League ต้องแก้ที่ `healUnit()` กับ `grantShield()` ใน `engine/damage.js`

### พาสซีฟ

อยู่ใน `engine/support.js` แยกเป็นสามกลุ่มตามจังหวะที่ทำงาน

| จังหวะ | ฟังก์ชัน | ของที่ใช้ |
|---|---|---|
| ตอนจ่ายฮีล/โล่ให้เพื่อน | `onHealOrShield()` | ats (ส่งต่อ 30%), acb (บัฟ AS + on-hit), sfv (บัฟ AP/AH) |
| ทุกเฟรม | `tickSupportItems()` | gwc (ออร่า), abw, hmb, pib, esb, ood (เลือกคนผูก) |
| ตอนดาเมจวิ่งผ่าน | `lifeBondSplit()` / `lifeBondLeech()` | ood (รับแทน 12% / ฮีลกลับ 8%) |

ของที่กดเองไม่มีปุ่มให้กด — เอนจินยิงให้เองตามเงื่อนไข (เพื่อนเลือดต่ำ, มีศัตรูเข้าระยะ, เพื่อนติด CC)
คูลดาวน์ลดตาม Item Haste ด้วย `cdrFromItemHaste()`

**ระวังเวลาเขียนออร่า** — `addBuff()` เป็นการ *ซ้อน* ไม่ใช่ *ต่ออายุ* ถ้าเติมบัฟใหม่ทุกเฟรม `buffSum()` จะบวกก้อนที่ยังไม่หมดอายุรวมกัน
(ตอนแรก Gjallarhorn ให้ +60 MS / +45% AS แทนที่จะเป็น +20 / +15%) ใช้ `addBuffUnique(u, tag, buff, now)` ใน `engine/state-util.js` แทน

**`HARD_CC` ของเอนจินนับ `slow` รวมอยู่ด้วย** — ของที่เป็น Cleanse คูลดาวน์ยาวอย่าง Hermes จึงใช้ `LOCKING_CC`
(ตัด slow ออก) เป็นเงื่อนไขจุดทำงาน ไม่งั้นจะถูกจุดทิ้งเพราะโดนสโลว์เฉยๆ

## โครงหมวดไอเทม (จัดใหม่)

เดิมหมวดปนกันระหว่าง "เทียร์" กับ "สาย" — ของเวทซ่อนอยู่ในหมวด HASTE ของแอสซาซินซ่อนใน FIGHTER
และหมวด TANK มี 16 ชิ้นเพราะนับชิ้นส่วน Tier 2 รวมเข้าไปด้วย ตอนนี้แยกสองแกนออกจากกัน

**ทุกชิ้นมีฟิลด์ `tier` (1/2/3)** และ **`cat` = สายหลัก** ส่วน **`also[]` = สายรองที่ใช้ร่วมได้**

| แท็บ | เป็นอะไร |
|---|---|
| `START` | ของเริ่มเกม ถือได้คนละชิ้น (6 ชิ้น — Chaos Blade / Scroll / Shield / Bow / Dagger / Chalice) |
| `T1` / `T2` | ชิ้นส่วนทั้งหมด แยกตามเทียร์ ไม่แยกตามสายแล้ว |
| `BOOTS` | รองเท้า (ADC ใส่โดยไม่กินช่อง) |
| `TANK` `FIGHTER` `ASSASSIN` `MAGE` `MARKSMAN` `SUPPORT` | **เฉพาะ Tier 3** สายละ 10 ชิ้น (เวท 15) |

`itemsInCat(cat)` คืน `{ own, lent, all }` — `own` คือของที่ `cat` ตรง ส่วน `lent` คือของที่มา `also`
หน้า ITEM/ร้านค้าเลยขึ้นสายหลักก่อนแล้วค่อยต่อด้วยของที่ยืมมา และพาดหัวบอกจำนวนแยกกัน
`inCat(it, cat)` ใช้เช็กว่าชิ้นนี้อยู่ในแท็บไหนได้บ้าง

**อย่าใช้ `cat` เช็กเทียร์อีก** — `tier3Count` ใน `stats.js` และ `buyBlockedReason` ใน `items.js`
ใช้ `it.tier === 3` แล้ว (เมื่อก่อนเช็กด้วย `!["START","PART","BOOTS"].includes(cat)` ซึ่งพังทันทีที่หมวดเปลี่ยน)

## สมองซื้อของของบอท — `game/shop-ai.js`

เดิมอยู่ใน `App.jsx` และดูแค่ `LANE_TASTE` ทำให้ **ไม่มีเลนไหนลิสต์หมวด FIGHTER เลย
บอทจึงไม่เคยซื้อของไฟท์เตอร์/แอสซาซินสักชิ้นตลอดทั้งเกม** ตอนนี้แยกออกมาเป็นโมดูลและคิดสองชั้น

1. **ชั้นสาย** — `champProfile()` อ่าน `role` ของตัวละครกับผลรวมสเกล AP เทียบ AD ของสกิลทุกท่า
   แล้วเลือก `ROLE_TASTE` (ตกไปใช้ `LANE_TASTE` เฉพาะตอนไม่รู้จัก role)
   ดูจาก role ไม่ใช่เลน ตัว Diver ที่โดนจับไปยืนเลนซัพก็ยังขึ้นของแอสซาซินถูก
2. **ชั้นแก้ทาง** — `readThreat(enemies)` สรุปทีมตรงข้ามเป็น `apShare` / `adShare` / `heal` / `bigHp` / `cc`
   แล้ว `counterScore()` บวกแต้มให้ของที่แก้ทางพอดี

| ทีมตรงข้ามเป็นแบบไหน | บอทจะเบนไปซื้อ |
|---|---|
| เวทเยอะ | ของต้านเวท (Mjölnir, Siren's Bell, Iron John) |
| กายภาพเยอะ | ของเกราะ (Osiris, Bleeding Centaur, Prometheus) |
| มีตัวฟื้นเลือด | ของตัดฮีล (Executioner's Nettle → Bleeding Centaur / Nemesis) |
| เลือดหนาทั้งทีม | ของเจาะ % และ %Max HP (William Tell, Eye of Horus, Achilles' Talaria) |
| CC เยอะ | ของ Tenacity (Asgardian Treads) |

`forbidden()` เป็นตัวกันซื้อมั่ว — ตัว AD ไม่แตะของ AP และกลับกัน, แทงค์ไม่ถือกริชเจาะเกราะ
ที่ไม่มีค่าอึดติดมา, ตัวประชิดที่ไม่ใช่ Skirmisher ไม่ซื้อของคริต
รองเท้าถูกบังคับให้เป็นของชิ้นที่สองเสมอ (ADC ซื้อได้ตั้งแต่แรกเพราะไม่กินช่อง)

ค่าสถานะใหม่รอบนี้คือ `antihealOnDmg: { v, dur }` — ติด buff `antiheal` ให้เป้าทุกครั้งที่ดาเมจเข้า
(`engine/damage.js`) ซ้อนกันไม่ได้ ใช้ตัวที่แรงสุดของคนใส่ (`engine/stats.js`)
บอทจะซื้อของตัดฮีลแค่ชิ้นเดียว — `counterScore()` เช็ก `haveAntiheal` ก่อนให้แต้ม
ไม่งั้นมันจะกวาดของตัดฮีลจากทุกสายมาใส่จนบิลด์เพี้ยน

ของตัดฮีลมีให้ทุกสาย ตัดเท่ากันหมด 40% นาน 3 วิ ตั้งแต่ชิ้นส่วน Tier 2

## กับดักที่เจอซ้ำแล้วซ้ำอีก — ออร่าที่เติมบัฟทุกเฟรม

`addBuff()` เป็นการ **ซ้อน** ไม่ใช่ **ต่ออายุ** และ `buffSum()` บวกทุกก้อนที่ยังไม่หมดอายุ
ของที่เติมบัฟใหม่ทุกเฟรมจึงมีบัฟค้างซ้อนกัน 3-18 ก้อนตลอดเวลา ทำให้ค่าบานปลายหลายเท่า
**เติมบัฟทุกเฟรมเมื่อไหร่ ใช้ `addBuffUnique(u, tag, buff, now)` เสมอ**

ที่เคยพังมาแล้วสามจุด

| ของ | ที่ตั้งใจ | ที่เกิดขึ้นจริง |
|---|---|---|
| Gjallarhorn's War Clarion | เพื่อน +20 ความเร็วเดิน +15% ความเร็วโจมตี | +60 / +45% (ซ้อน 3 ก้อน) |
| Mjölnir's Grounding Cloak | ครบ 10 ชั้นได้ +10% ความเร็วเดิน | สูงสุด +180% |
| Mirror of the Snow Queen | ศัตรูรอบตัว **−25%** ความเร็วโจมตี | ซ้อนจน `asEff` **ติดลบ** → `atkCd = 1 / asEff` ติดลบ → **ศัตรูตีได้ทุกเฟรม** (ทีมที่ถือแพ้ 100%) |

ตอนนี้ `u.asEff` มีเพดานล่าง `Math.max(0.15, ...)` กันไม่ให้ความเร็วโจมตีติดลบอีก
และออร่าชนิดเดียวกันจากหลายคนใช้แท็กกลาง (ไม่ผูก `u.id`) เพื่อไม่ให้บวกทับกันตามธรรมเนียม MOBA

## คำอธิบายสกิลเป็นภาษาคน

`skillSentence(sk)` ใน `game/skill-desc.js` ประกอบประโยคจากข้อมูลดิบของสกิล ไม่ได้พิมพ์มือทีละตัว
ต่อกันเป็นท่อนตามลำดับ: **ทำอะไร/ไปไหน → จังหวะเวลา → ชนิดดาเมจ → ล็อกศัตรูยังไง → ช่วยฝั่งเรา → ลูกเล่นพิเศษ**

ตัวอย่าง Ariel E — ข้อมูลดิบคือ `type: "submerge", range: 1100, submergeFixed: 1, surfaceDelay: 0.5, knockup: 0.5, magic: true`
ออกมาเป็น *"มุดลงไปใต้พื้น แล้วโผล่ขึ้นที่จุดเป้าหมายในระยะ 1100 หน่วย · อยู่ใต้พื้น 1 วิ · โผล่ขึ้นหลังจากนั้น 0.5 วิ · ทำดาเมจเวท · ลอยศัตรู (Knock Up) 0.5 วิ"*

**ข้อดีคือไม่มีทางหลุด** — ปรับตัวเลขใน`data/champions.js` ประโยคเปลี่ยนตามเอง และตัวละครใหม่ได้คำอธิบายฟรี
**เพิ่ม `type` ใหม่ต้องเติม case ใน `actionClause()`** ไม่งั้นจะได้ประโยคกลางๆ ว่า "ใช้สกิล"
ส่วนฟิลด์ผลพิเศษใหม่ (CC/บัฟ/ลูกเล่น) เติมใน `ccClause()` / `supportClause()` / `extraClause()`

## สีประจำค่าสถานะ

`STAT_C` ใน `ui/theme.js` จับคู่ชื่อฟิลด์กับสี — AD ส้มอมแดง, AP ม่วง, HP เขียว, เกราะเหลืองอำพัน,
ต้านเวทฟ้าอมเขียว, Ability Haste ทอง, ความเร็วเดินฟ้าอ่อน, เจาะเทาเหล็ก, ดูดเลือดชมพู, พลังฮีล/โล่มิ้นต์
ใช้ทั้งหน้าไอเทม ร้านค้า และแผงค่าสถานะในโมดัลสกิล **เพิ่มค่าสถานะใหม่ต้องเติมสีที่นี่ด้วย**
ไม่งั้นมันจะตกไปเป็นสีเนื้อความธรรมดาแล้วจมหายไปในบรรทัดอื่น

`ui/recipe.jsx` แยกข้อความไอเทมเป็นสามฟังก์ชัน แทนที่จะยัดรวมบรรทัดเดียวเหมือนเดิม

| ฟังก์ชัน | คืนอะไร | ใช้ที่ไหน |
|---|---|---|
| `itemStats(it)` | `[{ key, text, color }]` เฉพาะค่าสถานะดิบ | บล็อก STATS |
| `itemAbility(it)` | `[string]` ความสามารถ/พาสซีฟ | บล็อก ABILITY |
| `itemDesc(it)` | รวมทั้งหมดเป็นบรรทัดเดียว | แถวแคบๆ กับตัวกรองค้นหา |

**ถ้าเพิ่มฟิลด์ใหม่ต้องใส่ให้ถูกฟังก์ชัน** — ตัวเลขดิบไป `itemStats` ส่วนอะไรที่อธิบายพฤติกรรมไป `itemAbility`
ไม่งั้นบล็อก STATS จะมีประโยคยาวๆ ปนเข้ามาแล้วกลับไปอ่านยากเหมือนเดิม

## ยกฟาร์ม (Farm round)

EVENT ตัวใหม่ที่ **ข้ามการปะทะทั้งยก** ทั้งสองฝั่งได้เงินและ XP ราว 75% ของฝั่งที่แพ้

## ชั้นเอฟเฟกต์ (`ui/draw-fx.js`)

แยกเป็นสามชั้นที่วาดคนละรอบ และ**ทั้งสนามจริงกับห้องซ้อมเรียกฟังก์ชันเดียวกัน**
(เมื่อก่อนสองไฟล์นี้วาดพื้นแยกกัน พอเพิ่มโซนใหม่ก็ลืมไปเติมอีกไฟล์ โซนของ Alice เลยไม่ถูกวาดเลย)

1. `drawGround()` — โซน วงเตือน สนามน้ำ คลื่น กรง กับดัก โต๊ะน้ำชา อาณาเขตกระจก พายุโลหิต
2. `drawFx()` — ก้อนเอฟเฟกต์อายุสั้นจาก `state.fx` (ring · shock · flash · beam · trail · cone · aura · hit)
3. `drawFxText()` — ตัวเลขดาเมจกับป้ายชื่อสกิล มีขอบดำให้อ่านออกบนพื้นสว่าง

**กฎสำคัญ: ห้ามใช้ `Math.random()` ในตัววาด** ทุกอย่างต้องคำนวณจากตำแหน่งและเวลาเกิดของก้อนนั้น
(ฟังก์ชัน `hash()` ในไฟล์) ไม่งั้นประกายไฟจะกระพริบเปลี่ยนทิศทุกเฟรมเพราะวาดใหม่ 60 ครั้งต่อวินาที

ตัวกรองอายุเอฟเฟกต์ใน step.js เคารพ `f.dur` แล้ว — เมื่อก่อนฮาร์ดโค้ดไว้ที่ 0.55 วิ
เอฟเฟกต์ที่ตั้ง dur ยาวกว่านั้นจะหายกลางคันโดยไม่มีใครรู้

**การลอยของยูนิต** — `u.hurl = { fx, fy, tx, ty, start, until }` เอนจินลากตำแหน่งจริงไปตามเส้น
ส่วนตัววาดเติมความสูงเป็น `sin(k·π)` แล้ววาดเงาไว้ที่พิกัดพื้นเดิม ตัวละครเลยดูลอยข้ามสนามจริงๆ

## รอบบาลานซ์ตัวละคร (ก.ย. 2026)

วัดด้วย `_champ_bal.mjs` + `_bal_matrix.mjs` — เอาตัวที่วัดใส่แทนทีละช่องในทีมอ้างอิง
สู้กับทีมอ้างอิงชุดเดิม ครบทั้ง 5 เลน สลับฝั่งน้ำเงิน/แดงทุกคู่ ทุกฝ่ายซื้อของด้วยสมองบอท
วัดที่ Lv6/70g, Lv11/180g, Lv16/330g อย่างละ 20 ไฟต์ต่อช่อง (รวมราว 3,000 ไฟต์ต่อรอบ)

คะแนนที่รายงานคือ **ส่วนต่างจากค่ากลางของสนามในเลนนั้น** ไม่ใช่ชนะ% ดิบ
เพราะตัวประจำเลนของทีมแดงแต่ละเลนไม่ได้เก่งเท่ากัน (เจอ PINO ใครก็ชนะ)

**บทเรียนสำคัญ: 24 เมล็ดไม่พอ** — ครั้งแรกวัดได้ 38%/67% ในนัดกระจก (ทีมเดียวกันสู้กันเอง)
ซึ่งดูเหมือนมีอคติของฝั่ง พอขยายเป็น 100 เมล็ดกลายเป็น 44%/54% คือ noise ล้วน
เลขต่ำกว่า ±6 แต้มในตารางนี้อ่านเป็นความจริงไม่ได้

### สิ่งที่เปลี่ยนในรอบนี้

- คูลดาวน์อัลติทุกตัว **−50%** (ยก 30 วิไม่เคยได้ใช้อัลติเลย) — ผลคือ 66% → 93% ของตัวละคร
  ได้ปล่อยอัลติในไฟต์นั้น และปล่อยครั้งแรกที่วินาที 11 แทนที่จะเป็น 22
- ความเร็วเดินตัวประชิดลดจาก 364–376 เหลือ **345–355** ตัวไกลคงเดิม 330–335
  (ประชิดยังเร็วกว่าอยู่ราว 15–20 หน่วย) และปัดทุกค่าให้ลงท้าย 0 หรือ 5 รวมถึงไอเทมด้วย
- LORLA สเกลจาก Max HP → **Bonus HP** (ไอเทม + พาสซีฟ ไม่รวมเลือดฐาน) · พาสซีฟ +6 → +5
- TRISTAN Isolde 24% +1%/lv → **6.5% +0.5%/lv** และเพิ่มกติกา **โดนตีก็ได้ +5**
  (ออโต้นับทุกครั้ง สกิลนับครั้งเดียวต่อการร่าย ใช้หน้าต่าง 2 วิต่อป้ายที่มาของดาเมจ กัน DoT นับซ้ำ)
- PINO พาสซีฟ/W/R แรงขึ้น + เลือดและเกราะฐานเพิ่ม
- LUCH รื้อระบบพลังใหม่ทั้งหมด — ดูหัวข้อถัดไป
- C.HOOK เกราะ 25/+4.4 → 28/+4.8 · Q Bonus AD 0.8 → 1.0 · W 30–70% → 35–75%

### ระบบพลังใหม่ของ LUCH

เดิมออโต้ 1 ครั้ง = 1 ชิ้น ครบ 5 เข้าร่างเงา ปัญหาคือสกิลเขาไม่มีคูลดาวน์
เลยไม่ได้ประโยชน์จากไอเทมเร่งสกิลเลย ทั้งที่ไอเทมครึ่งค่อนเกมมี AH ติดมา

ตอนนี้เก็บเป็นหลอดเดียว 0–100 (`u.frag`) แล้วแปลงเป็น `light`/`shadow` ให้โค้ดเดิมอ่านต่อได้
ผ่าน `syncFrag()` ใน state-util.js — ออโต้โดน +20 · **AH ทุก 10 คืนให้ 1 ต่อวินาที** ·
ร่ายร่างแสงกิน 20 · เต็ม 100 เข้าร่างเงา · ออกจากคอมแบต 5 วิ เต็มทันที

แถมแก้บั๊กเก่าที่กฎ "อั้นชิ้นส่วน" ของ AI กลับด้าน — โค้ดเดิมสั่งไม่ให้ร่ายตอนชิ้นส่วนน้อย
แล้วปล่อยให้ร่ายตอนใกล้เต็ม ซึ่งทำให้เขาแทบไม่เคยเข้าร่างเงาเลยตลอดมา

**ภาษีชนะรวด** เริ่มเก็บตั้งแต่ชนะติดกันยกที่ 3 หักจากรายได้ทั้งก้อนของยกนั้น (ฐาน + โบนัสเลน + ค่าคิล)

| ชนะติดกัน | 1–2 | 3 | 4 | 5 | 6+ |
|---|---|---|---|---|---|
| เงิน | เต็ม | −10% | −18% | −25% | −30% |
| XP | เต็ม | −5% | −9% | −12.5% | −15% |

XP โดนครึ่งเดียวของเงิน (`TAX_XP_SHARE`) เพราะถ้าตัดเลเวลแรงเท่ากันจะกลายเป็นลงโทษคนเล่นเก่งเกินไป

**เงินชดเชยแพ้รวด** ได้เฉพาะยกที่ *พลิกกลับมาชนะ* — ต่อคน +1g ต่อหนึ่งยกที่แพ้ติดกัน (นับสูงสุด 5 ยก)
และ +1 XP ทุกๆ 2 ยกที่แพ้ติด เช่นแพ้ 3 ยกแล้วชนะ ทุกคนได้ +3g +2 XP (ทั้งทีม = +15g)

จูนด้วย `_streak_tune.mjs` ซึ่งจำลองรายได้จริงรวมค่าคิล เป้าหมายคือ **หน่วง ไม่ใช่ล้าง** —
ทีมที่เก่งกว่ายังต้องนำอยู่ แค่นำช้าลง ช่องว่างเงินสะสม 12 ยกเหลือราว 40–45% ของเดิม
(ถ้าเก็บภาษีหนักกว่านี้ ฝั่งที่แพ้จะรวยกว่าฝั่งที่ชนะ ซึ่งพังกว่าเดิม)

บอกผู้เล่นทางหน้า RESULT (บรรทัดสีทอง = โดนหัก, สีเขียว = ได้ชดเชย, บรรทัดจางคือของฝั่งแดง)
และป้ายเล็กบนหัวจอที่บอกว่าตอนนี้ชนะรวด/แพ้รวดอยู่กี่ยก

## รายการโปรด (Favourites)

ติดดาวไอเทมในร้านแล้วซื้อได้จากการ์ดนักแข่งในหน้าเตรียมยกเลย ไม่ต้องเปิดร้าน

`favs` เป็น state ระดับ App รูปแบบ `{ ช่องนักแข่ง: [id ไอเทม] }` — **แยกของใครของมัน**
`favsOf(idx)` อ่านของตัวนั้น `toggleFav(idx, id)` ติด/ถอดดาว และรีเซ็ตทั้งก้อนตอน `startMatch()`
หน้าร้าน (`ui/ShopScreen.jsx`) รับมาเป็นอาเรย์ที่ผูกกับตัวที่เปิดร้านอยู่แล้ว เลยไม่ต้องรู้จัก idx

แถบซื้อเร็วอยู่ใน `screens/Shop.jsx` หนึ่งบรรทัดต่อไอเทมที่ติดดาว
บรรทัดนั้นมีของใหญ่ตัวเอง แล้วต่อด้วย **ชิ้นส่วนที่ยังขาด** (ขึ้นต้นด้วย └) ที่ได้จาก
`buildRecipeTree` เดินลงไปเก็บใบที่ยังไม่มี — เงินยังไม่พอซื้อของใหญ่ก็ทยอยเก็บชิ้นส่วนได้เลย
ซื้อผ่าน `buy(idx, item)` ตัวเดียวกับร้าน เลยได้ตรรกะชิ้นส่วน/ช่องเต็ม/ห้ามออกซ้ำเหมือนกันฟรี

`buy()` เรียก `dropFav(idx, item.id)` ต่อท้ายเสมอ — **ซื้อของที่ติดดาวแล้วดาวหายเอง**
(ซื้อชิ้นส่วนย่อยไม่นับ ดาวของใหญ่ยังอยู่จนกว่าจะประกอบเสร็จ)

## หน้าไอเทม — หน้า ITEM กับร้านค้าในเกมใช้โค้ดชุดเดียวกันแล้ว

เดิมสองหน้านี้เขียนแยกกันคนละแบบ หน้า ITEM มีตาราง + แผงรายละเอียดที่ไล่ดูสูตรย้อนได้
ส่วนร้านค้าในเกมเป็นลิสต์เรียงลงมาเฉยๆ ตอนนี้ย้ายชิ้นส่วนที่ใช้ร่วมกันไป `ui/ItemPanel.jsx`

|---|---|

| `ItemGrid` | ตารางไทล์ + พาดหัวบอกจำนวน |

## ไอเทมที่ห้ามออกซ้ำกัน

ของบางกลุ่มทำงานทับกัน ซื้อสองชิ้นแล้วไม่ได้แรงขึ้นเป็นเท่าตัว แต่กินช่องกินเงิน
`UNIQ_GROUPS` ใน `data/items.js` เก็บชื่อกลุ่มไว้ ส่วนตัวไอเทมติดแท็ก `uniq: ["ชื่อกลุ่ม"]`
ชิ้นเดียวอยู่ได้หลายกลุ่ม (Shiva's Trishula อยู่ทั้ง `thirdhit` และ `antiheal`)

`uniqClash(items, item, consumed)` เช็กให้ และ `buyBlockedReason()` เรียกใช้
**ชิ้นส่วนที่กำลังจะถูกกลืนเข้าสูตรไม่นับว่าชน** ไม่งั้นจะอัพ Executioner's Nettle เป็น Bleeding Centaur ไม่ได้
บอทได้ผลนี้ฟรีเพราะ `shop-ai.js` เรียก `buyBlockedReason()` อยู่แล้ว (ทดสอบ 300 บิลด์ ไม่ชนสักครั้ง)

รายชื่อกลุ่มทั้งหมดอยู่ใน `docs/balance.md`

**ของที่กดใช้เองไม่ต้องจับกลุ่ม** — เคยจับ `teamsave` (Pridwen + Eir) กับ `horsbuff` (Aceso + Saraswati)
ไว้ด้วย แต่สองคู่นั้นเป็นของกดใช้/ของที่เสริมกัน ไม่ได้ทับกัน เลยเอาออกแล้ว ถือพร้อมกันได้
เกณฑ์คือ **ผลมันทับกันจนชิ้นที่สองแทบไม่เพิ่มอะไร** ไม่ใช่แค่ "ทริกเกอร์คล้ายกัน"

**ข้อความบล็อกต้องผ่าน `tr()`** — เดิม `buyBlockedReason()` คืนภาษาไทยดิบแล้ว UI เอาไปโชว์ตรงๆ
พอสลับเป็น EN ปุ่มซื้อจะขึ้นไทย และการเทียบ `blocked !== tr("เงินไม่พอ")` ก็ไม่เคยตรง แก้แล้ว

## เครื่องมือวัดบาลานซ์

สองตัว ใช้คู่กัน ตัวเดียวไม่พอ

**`_balance.mjs`** — ตีราคาค่าสถานะทุกชิ้นจากราคาชิ้นส่วน Tier 1 (bt2 = 7g/10 AD → AD ละ 0.7g)
แล้วเทียบกับราคาขาย ได้ % ความคุ้ม จับของที่สเตตัสเกิน/ขาดได้ทันที
เกณฑ์: Tier 3 ที่มีพาสซีฟ ~95-100% · Tier 3 ที่เป็นค่าสถานะล้วน ~105-110%

`_report.mjs` รวมสองตัวข้างบนเป็น `docs/balance.md` — ตารางทุกสายพร้อมธงว่าตัวไหนควรจับตา
รันใหม่ด้วย `WR_JSON=/tmp/wr.json node _power.mjs 20 && node _report.mjs "$(cat /tmp/wr.json)"`

**`_power.mjs`** — วัดของจริง แจกไอเทมให้ทีมน้ำเงินทั้ง 5 คน แล้วดู % ชนะทีมแดงที่ซื้อของด้วยสมองบอทเท่ากัน
จับของอึดที่ `_balance.mjs` มองไม่เห็นมูลค่า และจับบั๊กแบบ Snow Queen ได้
**อ่านข้ามสายไม่ได้** — ของ AP ที่แจกให้ตัว AD ด้วยจะดูอ่อนเกินจริง ใช้เทียบกันภายในสายเดียวเท่านั้น
และ baseline เองมีความคลาดเคลื่อน ±10% ที่ 20 ซีด ต้องต่างกันเยอะจริงถึงจะเชื่อได้

## ของที่ยังไม่เสร็จ บอกไว้ก่อน

- ระบบแบน Event ที่เป็นไอเดียหลักยังไม่ได้ทำ ตอนนี้เลยเลือกเองได้เลย
- ของเจาะเกราะมีแล้ว (wtb 10% / wtc 30%) แต่มีเฉพาะหมวดมาร์คแมน สายไฟท์เตอร์ยังไม่มี
- Discipline กับ Positioning ยังไม่ค่อยมีผลเท่า Reaction กับ Awareness
- ของสายซัพพอร์ตคุ้มแค่ ~84% ตามสูตร `_balance.mjs` แต่ถูกกว่าสายอื่น (47g เทียบ 61g) และพาสซีฟแรง เลยปล่อยไว้
- ตอนนี้มีตัวละครแค่ 8 ตัว และมีแค่ 3 ตัวที่มีสกิลฮีล/โล่ (LUCH, TRISTAN, PINO)
  ของสาย Enchanter ที่ทำงานตอน "จ่ายฮีล/โล่ให้เพื่อน" (ats/acb/sfv) จึงใช้ได้จริงกับตัวพวกนี้เท่านั้น
- ไฟต์ประมาณ 20% จบแบบหมดเวลาแล้วนับเลือดเอา ไม่ได้ล้างทีมกันจริง
- ตัวประชิดได้ตีจริงแค่ 30% ของเวลา เพราะโดนคุมระยะจนเข้าไม่ถึง

    modes.js              โหมดแมตช์ — จำนวนยก ยกที่ชนะ ตัวคูณเงิน/XP
    champions.js          ตัวละคร + สกิลทั้งหมด
    items.js              ไอเทม สูตรคราฟต์ หมวดร้านค้า
    tuning.js             Event, สไตล์ทีม, regen, retreat, damage ramp
    constants.js          ขนาดสนาม, เลน, ค่าสถานะพื้นฐาน
    lanes.js              เลเวลสูงสุด/ทองต่อยกของแต่ละเลน

  engine/               การจำลองไฟต์ล้วนๆ ไม่มี React รันใน node ได้
    build-fight.js        ประกอบ state เริ่มไฟต์จากทีมสองฝั่ง
    step.js               ลูปหลัก 60 ticks/วิ + runFight()
    ai.js                 ตัดสินใจว่าจะกดสกิลไหนตอนไหน
    targeting.js          เลือกเป้า, ประเมินภัยคุกคาม, หาจุดลง AOE
    fire-skill.js         ผลของสกิลแต่ละตัวตอนกด (สวิตช์ยาวตามชื่อสกิล)
    damage.js             คำนวณดาเมจ เกราะ ชีลด์ ฮีล
    on-hit.js             ทริกเกอร์ตอนออโต้/สกิลโดน (พาสซีฟตัวละคร)
    motion.js             ดash, grab, snipe
    systems.js            ระบบเฉพาะตัวละคร + โซนบนพื้น
    support.js            พาสซีฟไอเทมสายซัพพอร์ต (ออร่า, ฮีลหมู่, Life Bond)
    stats.js              แปลงค่าสถานะนักแข่ง/ไอเทม เป็นค่าจริงในไฟต์
    skill-ranks.js        ลำดับอัพสกิล Q/W/E/R
    state-util.js         buff, log, ระยะทาง, centroid (addBuff ซ้อน / addBuffUnique ต่ออายุ)
    util.js               random seed, clamp, ระบบเลเวล/XP

  game/
    shop-ai.js            สมองซื้อของของบอท (สาย + แก้ทางทีมตรงข้าม)
    roster.js             สุ่มนักแข่ง, ค่าคงที่ของแมตช์ (30 แต้ม, 16 ยกชนะ)
    skill-desc.js         แปลงข้อมูลสกิลดิบ -> บรรทัดที่คนอ่านรู้เรื่อง (ตารางป้ายชื่อฟิลด์)
    report.js             แปลง state ตอนจบไฟต์ เป็นตัวเลขสรุปให้หน้ากราฟ

  ui/                   ชิ้นส่วนที่ใช้ซ้ำหลายหน้า
    theme.js              สี + ฟอนต์ (C)
    chrome.jsx            Shell (หัวจอ), ปุ่ม, การ์ด
    widgets.jsx           Bar, Pip, Label
    Arena.jsx             canvas สนามรบ
    draw-fx.js            วาดเอฟเฟกต์/ตัวเลขดาเมจ
    ShopScreen.jsx        หน้าร้านค้า (โมดัล)
    SkillInfo.jsx         โมดัลข้อมูลสกิล — ค่าทุกแรงก์ + อัพแล้วได้อะไร
    Scout.jsx             หน้าส่องทีมคู่แข่ง (โมดัล) — ตัวละคร ของ เลเวล สกิล
    Stats.jsx             หน้ากราฟสรุปไฟต์ (โมดัล) — เส้นเวลา + แท่งรายคน + ที่มาของดาเมจ
    recipe.jsx            ต้นไม้สูตรคราฟต์ + คำอธิบายไอเทม
    Practice.jsx          ห้องซ้อมกับดัมมี่

  i18n.js               ตัวแปลภาษา — tr("ข้อความไทย") คืนอังกฤษตาม i18n-en.js
  i18n-en.js            พจนานุกรม ไทย -> อังกฤษ (350 ข้อความ) แก้คำแปลที่นี่

  ui/kit.jsx            ชิ้นส่วนหน้าตารวม — TwoPane, Tabs, TileGrid, Tile, Portrait, MenuButton

  screens/              หนึ่งไฟล์ = หนึ่งหน้าจอ รับ ctx ก้อนเดียวจาก App
    Menu.jsx              เมนูหลัก + เมนูเลือกโหมด (PLAY / RANK / TOURNAMENT)
    Store.jsx             CHARACTER STORE — แท็บตามเลน + ราคา (ยังไม่มีระบบเงิน)
    ItemBook.jsx          ITEM — คลังไอเทมทุกชิ้น สูตรคราฟต์ไล่ดูต่อได้
    Setting.jsx           SETTING — ความเร็วตั้งต้น เส้นระยะ รีเซ็ตแมตช์
    Pick.jsx              PICK — ตารางตัวละคร + Character Info + ลำดับอัพสกิล
    Setup.jsx  Position.jsx  Plan.jsx  Shop.jsx  Fight.jsx  Result.jsx

**เวลาจะแก้อะไร ดูตรงนี้**

| อยากแก้ | ไปที่ |
|---|---|
| ตัวเลขสกิล/ตัวละคร | `data/champions.js` |
| ผลของสกิลตอนกด | `engine/fire-skill.js` |
| ไอเทม / ราคา / สูตร | `data/items.js` |
| ค่าสถานะใหม่ของไอเทม (ต้องรองรับในเอนจิน) | `engine/stats.js` (deriveStats) + `ui/recipe.jsx` (itemDesc) |
| พาสซีฟไอเทมซัพพอร์ต (ออร่า/ฮีลหมู่/โล่หมู่) | `engine/support.js` |
| พลังฮีล-โล่ที่จ่ายออก (`hors`) vs ที่รับเข้า (`healAmp`) | `engine/damage.js` (`healUnit`, `grantShield`) |
| บอทเล่นโง่ | `engine/ai.js`, `engine/targeting.js` |
| บอทซื้อของโง่ / ไม่แก้ทาง | `game/shop-ai.js` |
| ของชิ้นนี้ควรอยู่แท็บไหน | `cat` + `also[]` ใน `data/items.js` |
| ไฟต์ยืดไป / จบเร็วไป | `data/tuning.js` (RAMP_FRAC), `engine/step.js` |
| หน้าตา UI ของหน้าไหน | `screens/<ชื่อหน้า>.jsx` |
| ชิ้นส่วน UI ที่ใช้ซ้ำ (แท็บ ตาราง สองฝั่ง) | `ui/kit.jsx` |
| เมนู / ลำดับหน้าจอ | `screens/Menu.jsx` + `App.jsx` (phase) |
| คำแปลอังกฤษผิด/อยากเปลี่ยนคำ | `i18n-en.js` (คีย์คือข้อความไทยเดิม) |
| สีธีม | `ui/theme.js` |
| ข้อมูลที่ส่องคู่แข่งได้ | `ui/Scout.jsx` |
| หน้าข้อมูลสกิล / ป้ายชื่อค่าสกิล | `ui/SkillInfo.jsx` + `game/skill-desc.js` |
| หน้ากราฟ / ตัวเลขที่โชว์ | `ui/Stats.jsx` |
| เพิ่มสถิติใหม่ที่เก็บระหว่างไฟต์ | `engine/damage.js` + `game/report.js` |
| จำนวนยก / เงินต่อยก / เพิ่มโหมดใหม่ | `data/modes.js` |
| เพิ่ม state ใหม่ให้ทั้งเกม | `App.jsx` (อย่าลืมใส่ใน `ctx`) |

> `screens/*.jsx` เป็นฟังก์ชันธรรมดา ไม่ใช่ React component — เรียกตรงๆ ว่า `SetupScreen(ctx)`
> เลยยังใช้ state ก้อนเดียวกับ App ได้เหมือนเดิมเป๊ะ ห้ามใส่ hook (useState ฯลฯ) ในไฟล์พวกนี้ ให้ประกาศใน `App.jsx` แล้วส่งผ่าน `ctx`
